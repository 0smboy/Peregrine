Peregrine is a Rust-first object-storage engineering platform built around a
**ground-up Rust rewrite of [OpenStack Swift](https://github.com/openstack/swift)**.
It targets byte compatibility on implemented, explicitly tested paths. It is an
advanced lab system, not a feature-complete Swift twin or a production drop-in
replacement.

<Aside type="note" title="Format fidelity over everything">
Swift's correctness lives in its formats: the ring, the account and container
SQLite databases, the on-disk diskfile layout, pickled hashes, crypto metadata,
HMAC signatures, and erasure-coded fragment archives. Peregrine uses Python
Swift as the oracle for scoped golden and live proofs. Consult the strict parity
matrix before planning any mixed rollout.
</Aside>

## Status

Core CRUD, replication, EC, and selected middleware paths have unit and
four-node lab evidence, and every push runs the full workspace suite in CI.
The S3 surface is scored by a strict [dual-oracle harness](/dual-oracle)
against Python Swift 2.33 — **49/8 as of 2026-08-17 (post-GATE), not GREEN**
(`docs/fairness-lab/S3-ALIGN-20260815.md`). `main` as of 2026-08-18 carries
the account-level 405 guard, version-index CAS, and the second scoreboard;
the live fleet is still Gate.
Important production and runtime-integration gaps remain. The
[strict parity matrix](/parity) defines the current claim boundary; the
stance is **IMPLEMENTED_SUBSET_ONLY**, and this documentation never claims
"full Swift compatibility" or production readiness.
