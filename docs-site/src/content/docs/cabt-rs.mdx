`cabt-rs` is a Rust rewrite of the `cabt` COSBench automation tool. It keeps the
same CLI shape and drives benchmarks through [cosbench-rs](/cosbench-rs) by
default (or a Java COSBench controller), storing state under `~/.cabt/`.

## Commands

| Command | Purpose |
|---------|---------|
| `run <target>` | run the `fool` suite or a single task like `64KB_write_100` |
| `list` | list finished tasks |
| `remove` | remove a result by wid, or clear `fool` results |
| `collect` | collect results into a CSV report |

A task name is `<size>_<op>_<workers>` — `4KB_read_128`, `1MB_write_32`,
`16MB_read_8`. The `fool` suite runs a fixed size × op × concurrency ladder.

## Targets

`cabt` auto-selects the Swift target when the classic swiftclient environment is
set:

```sh
export ST_AUTH=http://10.42.30.11:8085/auth/v1.0
export ST_USER=test:tester
export ST_KEY=azure-swift-2026.bench
export ST_ENDPOINT=http://10.42.30.11:8085/v1/AUTH_test   # pin storage; skip the LB hairpin
cabt run 64KB_write_64 --object-count 400 --container-count 4 --runtime 25
cabt list
cabt collect
```

<Aside type="note" title="ST_ENDPOINT">
`ST_ENDPOINT` pins the storage base to a specific address instead of following
the storage URL auth returns. It was added so a benchmark run from inside a
cloud load-balancer backend pool can bypass the Internal-LB hairpin limitation.
</Aside>

## Backends

`--backend cosbench-rs` (default; auto-Swift when `ST_AUTH` is set),
`swift` (tempauth), `java` (a Java COSBench controller), or `mock`.

In the production pass, a six-task sweep (4 KB / 1 MB / 16 MB × read / write)
completed with **0 failures**; reads reached 4,180 ops/s (4 KB), 1,346 MB/s
(1 MB) and 1,920 MB/s (16 MB). See [Performance](/performance).
