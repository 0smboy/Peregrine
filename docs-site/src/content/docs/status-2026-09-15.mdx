<Aside type="note" title="Re-attributed on 2026-09-18 — the theme bins are misleading">
A dual-oracle re-measurement changed what these 159 mean. The Ceph suite
asserts RGW behavior, so a raw Rust failure count cannot say whether a failure
is a Rust regression. Scoring the same 725 identities against Python Swift and
diffing by exact name gives **156 both-fail, 3 rust-only, 231 python-only**:
the Rust-attributable G5-B gap is **3 identities**, and Python Swift itself
fails 388 of the same 725. The `sts` bin (34, the largest) contains no engine
evidence at all — the suite config has no `[iam]`/`[webidentity]` section, so
those abort before a request is signed. The `select` bin (29) never reaches
S3 Select either: every test hardcodes `bucket_name = "test"` and aborts in
setup because same-owner re-create answers 409 on both Swift implementations.

Each of the 3 rust-only identities was then characterized and acted on the same
day:

1. **Configuration, not a defect.** On a body shorter than its declared
   `Content-Length` both implementations answer `400 RequestTimeout`, Python at
   60.1s (its default) and Rust at 600.4s (the lab's `client_timeout = 600`),
   which is longer than the harness waits. The owner approved aligning the lab
   to 60; after the reload the identity **passes**.
2. **Transient.** The `NameError` only fires when a just-created bucket is
   missing from ListBuckets; 10 rounds × 5 buckets showed 0 missing and it
   **passes** in the re-run. The underlying cause is the degraded replication
   below, so it can recur.
3. **Object-lock governance bypass — a deliberate divergence, not an
   oversight.** The wall was lifted and the code dug: the engine requires the
   bypass header *and* an explicit IAM Allow, pinned by two unit tests, making
   it stricter than AWS, RGW, and Python Swift. Awaiting an owner choice between
   recording the divergence and changing the authorization rule.
   Analysis: `tools/test-results/g5-score-20260918/WALL-LIFT-OBJECT-LOCK-BYPASS.md`.

The owner accepted the object-lock divergence on 2026-09-19 (class
`stricter-than-aws`), which changes no engine behavior and leaves the parity fix
open as engine work.

**Full 725 re-run, 2026-09-19**, same tip, `client_timeout = 60`
(`tools/test-results/g5-score-20260919/`): 485 passed, 156 expected, 1 accepted
divergence, 0 unexpected skips, 0 stale entries, and **1 unexpected** —

  not be read as a pure product measurement. Remediation options and their

  `tools/test-results/g5b-classify-20260918/LAB-FINDINGS.md` §2 — all three
