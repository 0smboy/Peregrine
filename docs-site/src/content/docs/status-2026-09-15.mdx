## Lab state recorded 2026-09-18

Read-only reconnaissance plus one bounded disk reclaim; prod `:8080`, the live
tip binary, `/srv/node/d{1,2,3}`, the overseer, and remint were not touched.
Full detail in `tools/test-results/g5b-classify-20260918/LAB-FINDINGS.md`.

- **Prod `:8080` runs the Rust proxy**, not Python: pid 3114191 =
  `/usr/local/bin/swift-proxy-server`, an ELF whose sha256 is the published
  `ab5cb95c…`, under a unit described `Swift proxy server (rust)`. The sha
  matches every prior claim, so nothing drifted; the 2026-09-15 Drive handoff
  simply mislabelled it. Python Swift is the separate pyswift `:8090`.
- **The lab's container/account replication is broken (G1).** Every replicator
  push to `10.0.4.2:6201/6202` is refused because the lab rings carry the
  production storage topology while the lab servers bind `127.0.0.1:16211/16212`.
  Backlog ≈ 15 900 `async_pending` entries. The directive requires G1 before
  G4/G5 scoring, so the census should not be read as a pure product measurement.
- **Disk:** swift1 `/` was at 1.7 GiB free (below the 3 GiB floor) with
  `/var/log/messages` growing ~300 MiB/day from that replication loop, and no
  `compress` in logrotate. After adding compression and rotating, **3.2 GiB
  free**; the 1.19 GB log compressed 36:1.
- swift1's Python oracle on `:8090` is running from a **deleted** virtualenv, so
  it must not be restarted. The 2026-09-18 baseline therefore used swift2.
