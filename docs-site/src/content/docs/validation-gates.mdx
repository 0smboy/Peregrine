## Gate contract

## G5 known-failure policy (owner decision 2026-09-18)

The G5 row above has always said "capability/known-failure policy, exact-name
diff, unexpected test names = 0". A separate owner override in force from
2026-09-15 additionally demanded that the **whole** Ceph s3compat set of ~725
pass. That override is **withdrawn**: the frozen policy is the bar.

The override was withdrawn because it measured the wrong thing. The Ceph suite
asserts RGW behavior, and the paired run on 2026-09-18 showed that of 159
FAIL+ERROR records at lab tip `9531eb62`, **156 also fail on Python Swift**,
which itself fails 388 of the same 725. Satisfying "all 725 pass" would have
required the Rust engine to deliberately diverge from Python Swift.

The policy lives in `tools/g5-known-failures/` and is generated, never
hand-edited. One rule keeps it honest:

> an identity may be frozen expected-fail **only if** the Python Swift oracle
> fails it too in the paired baseline run, or the harness cannot execute it.

So a failure that is Rust's alone is withheld from the list on purpose and
scores as unexpected; a frozen entry that starts passing is reported as a stale
entry and **fails** the gate until re-frozen. The list is not a blanket excuse,
and that is checked rather than asserted: scoring the Python baseline itself
against the policy yields 231 unexpected failures.

Score a run with `tools/g5-score.py RUN.xml --policy <policy.tsv>`. The
2026-09-15 census scored **FAIL with 3 unexpected**. The full re-run on
2026-09-19, same tip with the lab `client_timeout` aligned to the oracle, scores
485 passed, 156 expected, 1 accepted divergence, 0 unexpected skips, 0 stale
entries, and **1 unexpected** — the ListBuckets transient, which fails under
full-suite load and passes in isolation, and is attributable to the degraded lab
replication rather than the engine. So the last open G5-B identity is a **G1
environment defect**, and no engine change can close it.

Rust-only failures the engine chose on purpose are **never** written into the
generated policy, because that file earns its entries from the oracle. They go
in a separate hand-curated divergence list that the scorer only reads when given
`--divergences`, and each entry must name the document justifying it. Accepting
a divergence is an owner decision, not a measurement.

Evidence: `tools/test-results/g5-score-20260918/` and
`tools/test-results/g5b-oracle-diff-20260918/` (2026-09-18).

Withdrawing the override does not move G5 toward green on its own, and G5 is
still not green. The policy must be re-frozen against the G0-pinned Python
oracle commit `541a598…` rather than the swift2 deployment, configuration
parity (G2) must be established, the degraded lab replication must be fixed,
and G5-A has never been run on this tip.

## Evidence rules

- compare test names/identities, not aggregate counts;
- freeze collection lists before scoring;
- record skips, deselections, xfails, errors, timeouts, and collection failure;
- do not turn an environment failure into PASS;
- do not change assertions or known-failure classification during a scored run;
- preserve raw logs, manifests, summaries, and before/after hashes;
- a canary validates one hypothesis; rerun the complete frozen lane afterward;
- a later gate never repairs or replaces an earlier red gate.

## Test modes and host use

Compatibility, concurrency, and performance are separate modes. A host carrying
uncontrolled production traffic may still provide carefully labelled feedback
for a compatibility canary, but it cannot produce a valid concurrency or
performance acceptance result. The four Swift hosts may be used efficiently by
assigning fixed roles; they are not permission to run destructive suites in
parallel against shared state.

Parallelize source analysis, builds, unit tests, and isolated non-overlapping
canaries. Serialize any run that shares rings, databases, devices, daemon
state, ports, or frozen test namespaces.
