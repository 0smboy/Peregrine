The fleet does not run "latest main"; it runs **named binary generations**
with recorded SHA-256s, and the docs state which one is live. If a node
disagrees with this page, reconcile before touching anything
([health checklist](/runbooks#health-checklist-first-hour-of-any-shift)).

## Code tip vs live binary

`main` is deliberately allowed to be ahead of the fleet, and the difference
is tracked here rather than blurred:

- Live proxy = Gate generation (built 2026-08-17 from the merge-verified
  tree; source through commit `babb9c4`).
- Merge `a48a2b2` retired the last unmerged branch,
  `codex/hotfix-s3cmd-mb-live-8663-20260814`, into `main` with a verified
  resolution: the S3 layer was kept **byte-identical to main** (the hotfix's
  s3api rework was superseded by the F1→Size generations, which are
  dual-oracle verified live), while the proxy-side improvements were
  adopted and are now live in Gate.
- CI (`e78469a`): every push and pull request now runs the full workspace
  suite plus the EC slice on GitHub Actions; fmt/clippy debt is surfaced as
  report boards. The CI work also pinned liberasurecode ≥ 1.6.5 after
  reproducing a real upstream concurrency segfault
  ([lab notes](/lab-cluster#install-checklist)).

### Merged on `main`, awaiting the next proxy / object roll

- **Cross-proxy version-index CAS** (2026-08-17, PR #3): generation-fence
  create-only commit protocol; activation prerequisite is zero (works
  against the live Wave-2 object layer, which enforces
  `If-None-Match: *`). Red/green concurrency proof in CI;
  `docs/fairness-lab/VERSION-CAS-DESIGN-20260817.md`.
- **Account-level 405 guard** (2026-08-17, PR #7): signed `PUT /`,
  `DELETE /`, `POST /`, `HEAD /` now reject at the S3 layer with Python
  2.33's `405 MethodNotAllowed` (`ResourceType=SERVICE`). Live Gate
  still translates those into Swift `/v1/<account>` — a signed
  `DELETE /` with `allow_account_management=true` **deletes the tenant
  account**. Roll the proxy before exposing this path to anyone.
- **BUG-1 native-gate metadata POST** (PR #7): tagging-only / restore-only
  / transition-only sysmeta POST on a locked object is allowed. Mixed
  payloads that also carry lock keys stay denied. Needs an **object-server**
  roll; the live Wave-2 binary still has the mis-deny.
- **`clock_ok` wired, default off** (PR #7): `[filter:s3api]
  worm_clock_max_offset_ms` and the matching object-server knob. `0`
  (default) keeps historical `clock_ok=true`. `>0` is fail-closed against
  cached `chronyc -c tracking`. No behavior change until the knob is set
  after the next roll.

### Recorded gaps, next code windows

- Fence-object offline compactor with a safety proof (fences are permanent

- Second scoreboard `tools/strict-s3-supplement.py` (PR #8) is in-tree:
  extras 7/7 vs AWS semantics; account-root negatives 0/3 on live Gate
  (turns green only after the 405-guard proxy roll).

## Git branches

Product repo: `github.com/0smboy/Peregrine`.

| Branch | Role |
|--------|------|
| `main` | the line of record |
| `build/phase1-deploy-rs-lb` | deploy line — kept at the same tip as `main` |
| `codex/s3-align-20260815` | S3 alignment line — same tip |
| `codex/finish-cold-worm-20260814` | cold/WORM line — same tip |
| `codex/hotfix-s3cmd-mb-live-8663-20260814` | retired into `main` by merge `a48a2b2`; kept for history |
| `feat/cold…`, `cursor/…`, `honesty/…`, `chore/clippy…`, `chore/fmt…` | ancestors already contained in `main` — never re-merge |

The four product branches are pushed together so every line sees the same
history. Work starts from the current `main` tip; the historical dirty
working tree outside the product repo is never a merge source.

## Provenance strings

Every scored run names both binaries, e.g.
`peregrine@size+sha256:69d22629…` vs
`python-swift@2.33.0+s3api+object_versioning+xml-ct@10.0.0.3:8090` — reports
without provenance are not evidence.
