# Eventlet semantic matrix

Question is **why Swift needs the Eventlet primitive**, not how to build GreenThreads.

Oracle: Python Swift (`swift/common/wsgi.py`, `eventlet.GreenPool` / `Timeout` / green sockets).  
Target: Peregrine Concurrency Runtime (AGENTS.md) — Tokio+Hyper HTTP/1.1, bounded `TaskScope`, `BlockingDomain` / `ThreadedPosixIo` / `DbExecutor`.

**Current column (production `serve_forever_multi` / `serve_forever_multi_service`):** Tokio connection tasks; idle keep-alive is a pending Future; Handler still sync; **body fully buffered on async path**; SSYNC hijack broken on production serve (`Body::Buffered`); `spawn_blocking` only in `blocking.rs`.

There is no `read_raw_head`. Buffering is `IncomingBody::materialize` → `Body::Buffered` in `LegacyService::call` (`swift-http/src/server.rs:81-108`) and in object/account `handle_async` (`swift-object-server/src/lib.rs:565-582`; `swift-account-server/src/lib.rs:406-424`) **before** the sync `Handler`. `Body::hijack` is `None` on `Body::Buffered` (`swift-http/src/body.rs:227-231`).

That is **not** the target column: no Hyper; ABI is still `Handler = Arc<dyn Fn(Request) -> Response + Send + Sync>` (`swift-http/src/server.rs:49`); typed deadlines / `TaskScope` are **not** consumed. `AdmissionController` **is** constructed on the serve path, but every cap is the same `max_conn` (`server.rs:431-433`). Do **not** read `IncomingBody::next_chunk` as Phase 3 complete: production adapters fully buffer. Do **not** read leftover `handle_connection` Streamed+hijack as Phase 9 complete.

`worker_starvation` (2 workers + 2 idle keep-alives + 3rd GET) is currently **expected PASS** against this serve path at `spawn_server(2)`. That is Gate 1 for in-process HTTP idle. It is **not** “Eventlet solved” and it is **not** Gate 5. Do **not** raise workers.

## Citation convention

| Role | Tree | Path form |
|---|---|---|
| Eventlet / Swift oracle | this workspace's Python Swift | `swift/...:LINE` (and `etc/*-sample:LINE`) |
| Current Peregrine | this merge tree's HTTP serve (Tokio connection tasks + leftover sync Handler / legacy `handle_connection`) | `swift-rust/crates/...:LINE` |
| Target Peregrine | AGENTS.md runtime, **not fully on the serve path** | named type only |

Line numbers are inclusive ranges where a behaviour spans several lines. Re-check with `rg` before treating a number as a gate.

## Required coverage (AGENTS.md §3)

The seven behaviours below are why Swift adopted Eventlet. Each row: oracle (file:line) → why a greenlet existed → current Peregrine (file:line) → Peregrine **target**.

### Proxy fan-out

**Why Swift needs it.** One client PUT/GET/POST/DELETE must talk to several object/container/account nodes at once. Eventlet lets the proxy greenlet spawn sibling greenlets that share the hub; a blocked replica does not pin an OS thread.

| Step | Oracle | Current Peregrine | Peregrine target |
|---|---|---|---|
| Shared node cursor | `GreenthreadSafeIterator` + `Semaphore(1)` so concurrent `next()` cannot re-enter the generator (`utils/__init__.py:961-982`; GET `base.py:1661`; PUT `obj.py:799-801`; EC GET `obj.py:2970`). | `Arc<Mutex<Vec<Node>>>` popped from OS threads (`lib.rs:1533-1556`, `1618-1633`). | request-scoped `FanoutGroup` over a `NodeIter`; no OS thread per replica |
| Replica connect | `http_connect` under `ConnectionTimeout(conn_timeout)` then `Timeout(node_timeout)` (`base.py:2087-2097`, `1559-1568`). PUT: `Putter.connect` + `Expect: 100-continue` (`obj.py:804-812`, `1088-1107`, `1847-1872`). | `TcpStream::connect_timeout` + `set_{read,write}_timeout(node_timeout)` (`lib.rs:787-803`). PUT: `connect_putter` in a spawned thread (`lib.rs:1634-1656`). | async connect with `BackendConnectDeadline`; connect permit from admission |
| Concurrent GET | `GreenAsyncPile(self.concurrency)`; `waitfirst(concurrency_timeout)` when the pile is not full (`base.py:1663-1675`; conf `etc/proxy-server.conf-sample:304-319`). | **Sequential** on the client Handler: `get_or_head` `for node in nodes` + `backend_request_head` (`lib.rs:1990-2098`). `concurrent_gets` GreenAsyncPile is not present. ### Quorum

**Why Swift needs it.** Swift is eventually consistent; the proxy must decide success from a subset of replicas without waiting for the slowest, and must not treat a single 404 on a handoff as authoritative.

### Container updates

**Why Swift needs it.** After a durable object PUT/DELETE, listings must move. ## Explicitly not claimed

- **Hyper is not on the serve path** (`rg hyper` in `swift-http` → 0). Tokio `net` + a homemade HTTP/1.1 codec is not the ADR target.
- `TaskScope`, `FanoutGroup`, `QuorumTracker`, `DeviceScheduler`, `ThreadedPosixIo`, `DbExecutor`, typed deadlines, and hierarchical cancellation are **not** consumed by HTTP/proxy as the request ABI. `swift-http` imports `AdmissionController` / `AdmissionLimits` / `TrafficClass` (`server.rs:42`) and uses them with **identical** caps. It does **not** import `BlockingDomain`.
- Independent `max_connections` ≠ `max_active_requests` ≠ traffic-class budgets are unused. HTTP 503 is one `max_conn`.
- Connection tasks are `JoinSet::spawn` (`server.rs:481`), not naked discarded `tokio::spawn`. Runtime `TaskScope::spawn` still exists (`swift-runtime/src/scope.rs:296`) and is unused by HTTP/proxy/object. §5 required spawn to stay behind `TaskScope`.
- `rg` on this merge tree's `swift-rust/crates` (tests excluded): `spawn_blocking` → **16 identifier / 1 call**, all `swift-runtime/src/blocking.rs` (call at `:577`). `unbounded_channel` / `crossbeam_channel::unbounded` → **0**. Proxy fan-out **does** use unbounded `std::sync::mpsc::channel` (`lib.rs:1531`, `1619`, plus more in that file).
- **Current column (must hold):** Tokio connection tasks; idle keep-alive is a pending Future; Handler still sync; **body fully buffered on async path**; **SSYNC hijack broken on production serve (`Body::Buffered`)**; **`spawn_blocking` only in `blocking.rs`**. There is no `read_raw_head`. Buffering is `IncomingBody::materialize`, not a streaming Handler ABI. Stale text that said with-body is `BridgeRead` on `BlockingDomain` / `run_handler_with_body` is **not** this tree.
- `worker_starvation` **PASS** at `spawn_server(2)` does **not** mean Eventlet is solved. Do not raise `workers`. Gate 2 streaming ABI (body fully buffered; Handler still sync), Gate 3 blocking isolation (GET/HEAD + streamed response `Read` + PUT disk write on the runtime thread), Gate 4 overload memory (full-object buffer), Gate 5 (dual-feed, proxy `std::net`, SSYNC async session, eager-100 vs Python lazy-100) remain.
