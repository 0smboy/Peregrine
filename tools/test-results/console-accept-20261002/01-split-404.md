# 1. 创建桶 404 拆分

同一容器名 `console-accept-20261002`。先登录 Console，再拿本机 tempauth 的 token（token 未写入本文件）分别 PUT。顺序是 storage_url，然后 VIP。

| id | 方法 | 状态码 | 判定 |
|---|---|---|---|
| S-unauth | `GET http://127.0.0.1:9000/` | 303 `/login` | PASS |
| S-login-bad | `POST /login` tenant=test user=tester key=reject-this-key | 200 | PASS。页面含失败标记，没有 `sc_session` |
| S-login-good | `POST /login` 使用 swift4 `proxy-server.conf` 里的 `user_test_tester` | 303 `/files` | PASS。`Set-Cookie: sc_session`（值未记录） |

| S-put-vip | `PUT https://10.0.0.10:8085/v1/AUTH_test/console-accept-20261002` | 404 | FAIL。同一 HTML。tx `tx2b103fdc57c5b05101b0e-006abf8997` |

两枪都是 404。按计划，文件写入链整段 FAIL，不再把后续写入装成通过。

随后只读核对（仍未改账户）：

- 两次 HEAD 账户，间隔 2 秒，swift4 本机、10.0.0.1、10.0.0.3、10.0.0.4、VIP 都是 204。`x-account-container-count=0`。`x-put-timestamp=1790933686.19640` 与 `x-timestamp=1786692189.37280` 两次不变。
- account-server 日志（10:38:14Z）：swift3 和 swift4 `HEAD /d2/15623/AUTH_test 404`，`GET` 也是 404。
- container-server 日志：swift4 `PUT /d2/2441/AUTH_test/console-accept-20261002 201`，随后 `202`。swift3 同一 PUT 是 404。account-server 对 `PUT .../AUTH_test/console-accept-20261002` 是 404。
- swift4 账户库 `account_stat.status=DELETED`，`put_timestamp` 与上面的 `x-put-timestamp` 相同。`container_count` 列是 80，但客户端看到的是 0。容器表里已经有本轮这个名字（deleted=0）。
- 账户环：partition 15623，hash `f41c17e6415c98d5b7200e615237edd5`，主副本 d2 在 10.0.4.2、10.0.4.3、10.0.4.4。10.0.4.2 是已经停掉的 swift2。

判定对应计划里的「两枪都 404：账户在这套四节点上不可写，自动创建没有把容器建成」。更精确地说，库还在，但是 status 已是 DELETED，所以自动创建路径没有把容器 PUT 变成 201。
